## 浏览器业务验证

使用 `scripts/Test-Browser.ps1` 启动独立内存数据库并运行 Playwright，测试结束后自动停止服务。以下3条流程均已通过，业务测试数据不写入本地文件库。

1. **诊疗主流程**：收费员现场挂号和收款 → 医生填病历及初诊 → 多选检查申请 → 收费员勾选项目收费 → 检查医生分配登记并录入结果 → 门诊医生回看结果并提交确诊。主要操作通过实际页面完成。
2. **岗位与窄屏页面**：管理员排班、科室、目录、审计页面；药房库存与交易页；390×844窄屏登录页面可见且无横向页面溢出。
3. **处方到退款流程**：以API准备独立患者、挂号及初诊确诊，再通过页面开立处方、药房入库、窗口收费、核对发药、整项退药及窗口退款。最终核对项目已退费、只有一条退款记录、库存恢复为入库后的数量。

第1、2条在整体验证中通过；新增第3条修正测试定位后单独复验通过，避免重复已通过场景。三个场景运行的是相同版本应用包，均检查浏览器运行时异常为空。

此次修正了 Element UI 固定列按钮的测试定位、带图标按钮的可访问名称，以及错误HTTP方法的响应状态。失败期间的定位记录不代表最终验收结果。
