# 部署与运维

## 本地 H2 运行

运行 `Build.ps1` 构建，再运行 `Start.ps1`。默认监听 127.0.0.1:8080，日志在 `.runtime/server.out.log` 和 `.runtime/server.err.log`。`Stop.ps1` 根据保存的进程编号和启动时间校验，只停止该工程实例。

服务重启不会清除数据。示例排班仅在开发种子开启时补足未来7天；业务操作不会修改已存在排班。旧 Node MVP 数据保留原目录，本版本没有自动导入，避免把演示状态当成真实病历。

## MySQL 8

现有 MySQL 创建 UTF-8 数据库和独立业务账号，再通过环境变量启动：

```powershell
$env:SPRING_PROFILES_ACTIVE='mysql'
$env:DB_URL='jdbc:mysql://127.0.0.1:3306/cloud_his?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai'
$env:DB_USER='his'
$env:DB_PASSWORD='<数据库独立密码>'
$env:HIS_INITIAL_PASSWORD='<首次管理员初始密码>'
$env:HIS_SEED='false'
java -jar backend/target/cloud-his-1.0.0.jar
```

Flyway 自动执行版本迁移。不要向空库导入原素材 `his.sql`，本工程的表结构以迁移文件为准。首次只有 `admin`；登录后新增科室、对应岗位账号、医技目录、药品和医生排班，即可开始使用。

## Docker Compose

```powershell
Copy-Item .env.example .env
# 编辑 .env，替换所有示例密码
docker compose up --build -d
docker compose logs -f app
```

数据库不发布主机端口，只在 Compose 网络可见。应用默认发布 127.0.0.1:8080。MySQL 数据保存在命名卷 mysql_data。`docker compose down` 保留该卷，`down -v` 会删除数据库，不能用于日常停机。

首次验收可设置 `HIS_SEED=true` 生成开发数据；切换为 false 只停止后续注入，不删除已存在账号和示例患者。业务环境应使用新库并设置 false。

## HTTPS 和生产配置

完成医院验收后，可启用 `SPRING_PROFILES_ACTIVE=mysql,prod`，设置独立 `HIS_INITIAL_PASSWORD`、`DB_PASSWORD`，并通过 Nginx/Caddy 提供 HTTPS。`prod` 强制 Secure Cookie，因此直接 HTTP 登录不会保存会话。建议仅向反向代理开放应用端口，避免数据库和内部服务对公网暴露。

默认会话保存在单进程内；应用重启需要用户重新登录。若部署多实例，应接入共享会话（如 Spring Session），不能简单增加副本。

## 备份和恢复

- H2：先停止本项目，复制 `.runtime/data/`，恢复时在服务停止状态放回原目录。不要边写边复制单个数据库文件。
- MySQL：使用独立备份账号执行 `mysqldump --single-transaction --routines --triggers cloud_his`，密码通过受控配置或交互输入提供。定期在隔离环境实际恢复，不只检查备份文件存在。
- 数据库迁移随代码版本发布；新迁移新增 V3、V4，不改历史 V1/V2。发布前备份，先用备份库演练升级。
- `GET /api/health` 检查数据库连通性。业务异常可用响应参考号查询服务日志；日志和数据库访问权限应由运维管理员限制。
