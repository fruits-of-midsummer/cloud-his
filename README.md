# 云医院 HIS 门诊管理系统

本工程依据素材集中的《东软云HIS医院管理系统需求规格说明书》《需求陈述说明书》实现门诊业务，覆盖挂号收费、门诊医生、检查、检验、处置及药房六个业务域。它是可构建、可持久化、可验证和可部署的完整课程项目；原 `云医院HIS-MVP` 保留作流程原型，两个工程数据互不覆盖。

## 在当前电脑上运行

以下命令用于包含 `backend/`、`frontend/` 和 `Build.ps1` 的源码根目录。若你打开的是 ZIP 解压后的运行包，请按包内的专用 README 双击“启动.cmd”，运行包无需构建。

安装 Java 17+、Node.js 18+。首次构建需要网络；脚本会寻找本机 Maven，缺少时下载到项目 `.runtime/tools`。

在本目录打开 PowerShell：

```powershell
.\Build.ps1
.\Start.ps1
```

浏览器打开 **http://127.0.0.1:8080**。停止本项目服务使用 `Stop.ps1`。如果 PowerShell 阻止脚本，可仅对该次进程执行 `powershell -ExecutionPolicy Bypass -File .\Start.ps1`。

已经构建完成后，也可以直接双击本目录的 **启动.cmd**，脚本会启动服务并打开浏览器；双击 **停止.cmd** 结束本项目服务。

构建脚本执行前端生产构建、后端集成测试及 JAR 打包。JAR 已包含前端，因此运行时只需要 Java：

```powershell
java -jar backend/target/cloud-his-1.0.0.jar
```

本地默认使用 H2 文件数据库；`Start.ps1` 的数据位于 `.runtime/data/his.mv.db`，直接运行 JAR 则位于启动工作目录的 `data/`。重启保留数据，不会重置患者或业务记录。不要在服务运行期间移动数据库文件。

## 开发账号

开启开发种子数据时，下列账号首次创建的密码默认为 `His@2026!!`。可以在首次启动前设置 `HIS_INITIAL_PASSWORD` 覆盖，密码不会在重启时被重置。登录后可在右上角修改密码。

| 账号 | 岗位 | 能力 |
| --- | --- | --- |
| admin | 系统管理员 | 所有模块、科室、用户、排班、项目目录、审计 |
| cashier | 挂号收费 | 患者登记、挂号收款、退号、收费退费、打印凭证 |
| doctor | 全科门诊医生 | 本人患者病历、申请、确诊、处方、结果与费用 |
| doctor2 | 内科门诊医生 | 同上，不能访问其他医生患者资料 |
| check | 检查医生 | 本科室检查登记、分配与结果录入 |
| lab | 检验医生 | 本科室检验登记、分配与结果录入 |
| treat | 处置医生 | 本科室处置登记、分配与结果录入 |
| pharmacy | 药房药师 | 已缴费药品发退药、入库、库存与交易记录 |

种子数据创建示例患者、服务目录及未来7天的医生排班。药品初始库存为0，先由药房“药库查询 / 入库”登记入库，之后才能发药。种子初始化幂等，不覆盖已存在数据。

## 完整业务操作

1. 收费员选择或登记患者，选择当天科室、号别、医生及时段，确认病历本、支付方式和实收金额，完成挂号收款。
2. 门诊医生在本人队列中选择患者，填写病历首页和初步诊断并保存。未看诊挂号此时转为看诊中。
3. 医生按目录选择检查或检验，可多选并填写部位、目的和备注；已确诊患者还可开处置。
4. 收费员按姓名或病历号查询就诊，勾选未收费项目收款，查看或打印收款凭证。
5. 对应科室账号为已收费项目分配执行医生并登记，分配的医生录入结果；医生工作站可回看结果。
6. 门诊医生提交确诊后开立多药品处方，填写数量、用法、用量、频次、使用天数和嘱托。
7. 窗口收取药品费用后，药房核对并发药；库存与发药流水同时更新。
8. 未登记医技项目可按项退费；已发药必须先药房整项退药，再由窗口退费。所有退款保留原收费关联。
9. 医生在全部项目完成或撤销后结束就诊，病历转为只读。

## 工程结构

```text
cloud-his/
  backend/       Spring Boot + Spring MVC + MyBatis，业务服务及数据库迁移
  frontend/      Vue 2.7 + Element UI + Axios + Vite，按岗位划分页面
  docs/          需求对应、架构决策、接口、部署及验证记录
  scripts/       构建辅助脚本
  Build.ps1      一键构建和后端测试
  Start.ps1      后台启动并检查健康状态
  Stop.ps1       只停止本项目记录的进程
  Dockerfile     前后端多阶段构建
  compose.yml    应用 + MySQL 8
```

## 前后端独立开发

```powershell
# 终端1，从 backend 运行（需要 Maven）
mvn -s ../.mvn/settings.xml spring-boot:run
# 终端2，从 frontend 运行
npm ci --registry=https://registry.npmjs.org
npm run dev
```

前端开发地址 http://127.0.0.1:5173，`/api` 同源代理到 8080 后端，无需开放跨域。修改服务器地址时同步修改 `frontend/vite.config.js`。

## 验证

```powershell
# backend 目录
mvn -s ../.mvn/settings.xml test
# frontend 目录：先准备独立的开发服务（默认8086）
npx playwright test
```

本机也可在项目根目录运行 `scripts/Test-Browser.ps1`，它自动启动独立内存数据库测试实例，执行结束后关闭实例。只复验药房流程可用 `scripts/Test-Browser.ps1 -Grep '处方页面'`。本次验证结果见 [验证记录](docs/验证记录.md)。

后端测试使用独立内存数据库。浏览器测试会在所指向的数据库创建测试业务，只应指向独立测试实例。默认使用本机 Edge；可以设置 `E2E_BROWSER=chrome`、`E2E_BASE_URL`、`E2E_PASSWORD`。

MySQL 部署与备份见 [部署说明](docs/部署说明.md)，业务规则和范围见 [需求实现对照](docs/需求实现对照.md)，接口约定见 [接口说明](docs/接口说明.md)。

本次实现按原课程采用 Vue 2 和 Element UI，二者的长期维护升级应纳入正式上线计划。真实医院上线还需独立完成 MySQL 环境验收、医疗数据安全评审、外部支付/发票/叫号对接及医院业务验收；本工程不以开发测试代替这些验收。
